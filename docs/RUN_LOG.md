# Run log

What happened while building and running the experiments, including problems and how each was handled. Times are UTC.

## Before Phase 1 (30 Oct 2026)

- **Harness built** on AgentDojo 0.1.35 (benchmark v1.2.2). Two AgentDojo behaviours matter for non-English tests:
  1. Its tool-output formatter turns non-Latin text (Hindi, Bengali, Telugu) into `\uXXXX` escape codes in some structured outputs. We render text as written (`--tool-output unicode`, the default here).
  2. Some task checks compare against English words in the agent's reply. We also report a "state-only" version of task success that ignores reply wording.
- **Model choice (pilots in `results/pilot/`).** Gemini 2.5 Flash was no longer available to new API users. Gemini 3.x models needed a fix to send back "thought signatures" between tool calls. Gemini 3.5 Flash (non-Lite) is limited to 20 requests/day on the free tier, too few for this study. Chosen: Gemini 3.5 Flash-Lite and the open-weight Gemma 4 26B.
- **Translations.** Generated by an AI model, then checked by `validate_translations.py`. All four translators flagged Slack messages that the benchmark matches word for word, so these were added to the protected spans. Review sheets came back with 6 corrections (4 Hindi, 2 Telugu), applied and re-validated.

## Known limitations of the logs

- A record's `condition_id` does not include the output cap or timeout. That is why the resumed English run silently mixed settings until the audit caught it.
- `analyze.py`'s `errors` column counts every error line, including ones later replaced by a successful retry. For Gemma English it shows 2; the true number of excluded cases is 1.
